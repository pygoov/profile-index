# Браузерные чаты

## Суть проекта

Браузерный диалоговый интерфейс объединяет текстовое и голосовое взаимодействие в одном потоковом пользовательском опыте. Серверная часть координирует диалог, распознавание и синтез речи через заменяемые адаптеры, а браузер управляет микрофонным вводом, состоянием интерфейса и воспроизведением результатов.

## Мой вклад

Я спроектировал и реализовал серверную и браузерную части, координацию потоков и модель состояния интерфейса. Вклад охватывал жизненный цикл сессии, передачу микрофонного аудио, обработку событий диалога, сопоставление сообщений с синтезированными фрагментами и контролируемое завершение либо восстановление операций.

## Проявленные компетенции

- разработка асинхронных full-stack-систем;
- работа с браузерным аудио и потоковым пользовательским интерфейсом;
- управление сессиями и конкурентными операциями;
- координация типизированных событий между клиентом и сервером;
- потоковая доставка данных, отмена и обработка восстанавливаемых ошибок;
- разделение контроллеров и клиентских хранилищ состояния.

## Архитектурная эволюция

Браузерный канал был выделен в самостоятельную границу поверх общих адаптеров речи и диалога. Серверные контроллеры отвечают за оркестрацию и транспорт, а клиентские хранилища — за состояние интерфейса и воспроизведение. Такое разделение позволяет менять речевые и диалоговые компоненты, не перестраивая браузерный сценарий целиком.

## Ключевые особенности

Web Audio API обеспечивает захват и обработку микрофонного сигнала. WebSocket поддерживает двунаправленный поток, а NDJSON — последовательную доставку событий без ожидания полного результата. Синтез речи может выполняться параллельно, при этом корреляция событий связывает сообщение с соответствующим аудио. HTTP range позволяет доставлять аудиофрагменты частями. Отмена, повторяемые сбои и очистка неактивных сессий встроены в общий жизненный цикл взаимодействия.

## Технологический контекст

Серверная часть основана на Python, asyncio, ASGI, Starlette и msgspec; транспорт использует WebSocket, HTTP и NDJSON. Браузерная часть применяет JavaScript, HTML/CSS и Web Audio API. Для аудиоматериалов предусмотрена интеграция с S3-совместимым объектным хранилищем.

## Перспективы развития

Архитектура допускает внешнее хранение сессий, горизонтальное масштабирование, развитие доступности интерфейса и единую модель восстановления потоковых операций. Заменяемые адаптеры позволяют подключать другие речевые и диалоговые реализации без изменения базового пользовательского сценария.
