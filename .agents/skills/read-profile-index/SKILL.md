# Чтение Profile Index

Читай Markdown-дерево как иерархию с идентичностью по путям. Эта процедура строго доступна только для чтения.

## Когда использовать

Используй для поиска, обобщения, сравнения и объяснения проектов, вклада, компетенций, архитектуры или навигации этого портфолио.

Не используй для общих вопросов о Markdown, не связанных с репозиторием. Если может измениться файл, каталог, навигация или состояние Git, используй `edit-profile-index`.

## Процедура

1. Прочитай корневые `AGENTS.md`, `README.md` и `index.md`. Для вопроса о профессиональных возможностях также прочитай `competencies/README.md` и относящиеся к запросу дочерние документы о компетенциях. Готово, когда известны границы репозитория и область навигации.
2. Найди запрошенный узел через `index.md` и считай его относительный путь идентичностью. Готово, когда каждый выбранный путь присутствует в индексе и существует в дереве.
3. Прочитай `projects/README.md`, затем для каждого выбранного узла прочитай `README.md` каждого предка — от верхнеуровневого проекта до самого узла. Если запрошено поддерево, рекурсивно найди и прочитай все `README.md` его потомков. Готово, когда зафиксированы число выбранных узлов и число фактически прочитанных карточек.
4. Отвечай только по прочитанным файлам. Различай идею проекта, заявленный вклад владельца, проявленные компетенции, архитектурную эволюцию и потенциальное развитие. Считай `competencies/` синтезом: переходи по ссылкам к подтверждающим карточкам, когда они указаны; явно помеченный подтверждённый владельцем дополнительный опыт без проектной ссылки передавай как неподкреплённый карточкой, не удаляя его и не придумывая проект. Готово, когда каждое существенное проектное утверждение соотнесено с путём карточки, а основание каждой использованной компетенции обозначено точно.
5. Сохрани уровень приватности и атрибуцию исходного текста. Используй нейтральные ко времени формулировки и опускай неизвестное. Готово, когда ответ не содержит неподтверждённых утверждений о единоличном авторстве, текущей занятости, сопровождении, активной разработке, датах, метриках, результатах или частных субъектах.

## Ограничения и типичные ошибки

- `index.md` — навигация, а не второй реестр фактов.
- `.agents/skills/` описывает процедуры AI-агентов, а `competencies/` — профессиональные компетенции владельца.
- Дочерняя карточка не заменяет предков; всегда читай полную цепочку.
- Родительское резюме не заменяет потомков при запросе всего поддерева.
- Похожие названия не объединяют идентичности: идентичность задаёт путь.
- Отсутствие проектной ссылки у явно отмеченного дополнительного опыта не делает его недействительным и не разрешает выводить вымышленный проект.
- Не открывай `IDEA.md`, рабочий монорепозиторий, удалённые исходные материалы или историю Git для обогащения ответа.

## Проверка

- Перечисли прочитанные относительные пути и сообщи числа выбранных узлов и прочитанных карточек.
- Подтверди, что каждый выбранный узел найден через `index.md`.
- Подтверди, что каждое существенное фактическое утверждение опирается на прочитанную карточку или явно помеченный дополнительный опыт.
- Для каждой использованной компетенции укажи разрешившуюся ссылку на проект либо её явный статус дополнительного опыта без проектной ссылки.
- Подтверди сохранение атрибуции, нейтральности ко времени, приватности и пропуск неизвестного.
- Подтверди, что файлы и состояние Git не изменились.
